E-commerce Inventory API

REST API for managing the product inventory of an e-commerce store, built with Java 17, Spring Boot 4 and PostgreSQL, following a hexagonal architecture (ports and adapters) so the business logic stays independent from frameworks and the database.

Status: work in progress. Product creation and listing are working; authentication (JWT), validation and API documentation are being added. See the Roadmap.

Architecture

The project separates the core business rules from the technical details:

inventory-api/src/main/java/com/inventory/api
├── domain
│   ├── model/        # Business entities and rules (Product)
│   ├── repository/   # Ports: interfaces the domain needs (ProductRepositoryPort)
│   └── service/      # Use cases (ProductService)
└── infrastructure
    ├── adapter/
    │   ├── entity/       # JPA entities (ProductEntity)
    │   └── repository/   # Adapters implementing the ports (ProductRepositoryAdapter + Spring Data repository)
    ├── config/           # Spring configuration (beans, security)
    └── rest/             # REST controllers (ProductController)

Request flow:

HTTP request → ProductController → ProductService → ProductRepositoryPort
                                                           ↑ implemented by
                                              ProductRepositoryAdapter → PostgreSQL

Key points:

The domain layer has no dependency on Spring or JPA. ProductService only knows the ProductRepositoryPort interface.
Persistence lives in infrastructure: ProductRepositoryAdapter maps between the domain Product and the JPA ProductEntity, so changing the database or ORM does not affect the business logic.
Business rules (for example, reducing stock) live inside the domain model and are unit tested without starting Spring.
Getting started
Prerequisites
Java 17+
Docker and Docker Compose
Run locally

The Maven project lives in the inventory-api folder, so run everything from there:

bash
git clone https://github.com/luu199/e-commerce-inventory-api.git
cd e-commerce-inventory-api/inventory-api

# 1. Start PostgreSQL
docker compose up -d

# 2. Start the API
./mvnw spring-boot:run

The API will be available at http://localhost:8080.

Default local configuration

Defined in src/main/resources/application.yml (development values only):

Property	Value
Database	inventory_db on localhost:5432
User / password	postgres / postgres_password
Server port	8080

The schema is generated by Hibernate (ddl-auto: update) for development. Versioned migrations with Flyway are planned.

Example

Create a product:

bash
curl -X POST http://localhost:8080/api/products \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Laptop",
    "description": "15-inch laptop",
    "price": 2500.00,
    "stock": 10
  }'

List products:

bash
curl http://localhost:8080/api/products
Tests
bash
cd inventory-api
./mvnw test

Current coverage focuses on the domain model (ProductTest):

Reducing stock when enough units are available
Allowing stock to reach zero
Throwing an exception, without modifying stock, when there are not enough units
Design decisions
Hexagonal architecture: keeps business rules testable without Spring and makes infrastructure (database, web layer) replaceable.
BigDecimal for prices: avoids floating-point rounding errors in monetary values.
Separate domain model and JPA entity: the domain Product is not tied to persistence annotations; the adapter handles the mapping.
